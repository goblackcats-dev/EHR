# Verification brief (Burn ICU case study, one shift per checker)

You are the quality checker for ONE shift of the case study. Work in /home/user/EHR/casestudy/cases/burn_icu. The case study is built from `author.py` (Shift 1 items are in author.py; Shifts 2-6 are in shift2_items.py ... shift6_items.py). The chart the students use is `patient.json` (canonical case; `notes`, `observations`, `orders`, `administrations`, `ioEvents`, `devices`). The EHR shows hourly vitals/labs/I&O etc.; the shift totals the I&O flowsheet displays are in `ehr_io_totals.txt` (use those, not your own sums). `TIMELINE.md` is a readable dump of the chart. `SHIFT_AUTHORING.md` explains the rules the shift was written under.

## Check EVERY item of your shift (read it as the student sees it, then as the grader)
1. **Facts match the EHR.** Every number, time, name, order text, drug rate, lab value, note statement, and "where to look" path in the prompt AND in every answer-key element must match `patient.json` (script it: load the JSON and print the real values; do not trust memory). Read the actual note text when a key cites a note. Fix wrong values, wrong times, wrong units, wrong arithmetic. Verify all math (infusion mL/h, mcg/kg/min, Parkland, calories, unit conversions) by computing it.
2. **No future leakage / answerable at the time.** A student works with the clock set to the shift start and moving forward. Nothing in the questions may depend on chart data time-stamped after the END of the shift (check `collected`/`availableAt`/`datetime`/`orderedAt`/administration times). Results appear in the EHR at their `availableAt`/`collected` time.
3. **Images match.** Open each image in `images` (Read tool) and make sure the question and key describe what it actually shows (axes, times, values, labels). Do not describe things the picture does not show; the caption must not give away the answer.
4. **Points distribution.** Item points add up to 16 for Shifts 2-6 (20 for Shift 1); element points add up to the item points (or the item is a marked bank); points are sensible (harder reasoning earns more; pure look-up earns less); about one hour of work in total. Run `python3 check_shift.py shiftN_items.py` (Shifts 2-6).
5. **Clinical accuracy and fairness.** Doses, ranges, protocols, nursing priorities must be correct and standard (cite common references from memory only for things you are sure of; if unsure, soften the key to "accept ... or equivalent"). Keys must accept reasonable alternative answers (include "accept ..." ranges). Prompts must be unambiguous (a student must know what to write). Flag and fix questions that have no answer in the chart.
6. **Style.** Plain language, no em dashes, no bold markdown, ASCII only, consistent with the other shifts. Do not change the format or the number of items unless an item is broken; fix in place. Keep the total points of the shift unchanged.

## Output
Edit ONLY your shift's items (in your shift file; for Shift 1 only the Shift 1 items in author.py and nothing else in that file). Do not touch patient.json, notes, gen/, figures or other shifts' files. When done reply with a SHORT report: number of problems found and fixed (list each as "item: what was wrong -> fixed to"), anything you could not resolve (e.g. needs a chart change), and confirm `check_shift.py` OK (Shifts 2-6) and the point total.
